# DJOneHub 多模块实施计划

## 目标范围

通过带独立供电的 USB Hub 同时管理多个大疆第一代 4G 模块。每台模块独立提供状态、短信、来电、eSIM、AT 和通知配置；第一阶段只允许一台模块进入上网模式，不实现多链路聚合。

## 里程碑 1：多设备基础链路（已完成）

- 使用 libusb 完整枚举 `2ca3:4006`，不再打开第一个匹配设备。
- 使用 USB bus + port chain 识别当前物理连接，按指定设备打开 AT interface。
- 读取 IMEI 并生成不暴露完整 IMEI 的稳定 Device ID。
- 为每台模块创建独立 Runtime、轮询协程、eSIM Manager 和操作锁。
- 增加两秒一次的热插拔 reconcile；单台掉线不停止其他模块。
- 增加 `/api/devices` 和 `/api/devices/{deviceID}/...` 路由。
- 页面增加模块选择、离线状态和本机别名。
- Bark 配置按 Device ID 隔离，并迁移旧单模块配置。
- 对上网模式增加单模块 owner 保护。

## 里程碑 2：真机验证与稳定性（下一步）

- 使用 2 台和 4 台模块验证冷启动、热插拔、Hub 断电恢复和枚举顺序变化。
- 验证模式 0/1 切换后的 Product ID、port chain 和 AT interface 是否保持预期。
- 验证同时收短信、同时来电、跨模块发送短信无串台。
- 验证一台模块执行 eSIM 下载/切换时，其他模块持续可用。
- 记录 Hub 供电不足、USB timeout、interface claim 失败的可诊断错误。
- 根据实测调整启动并发数、轮询抖动和掉线退避。

完成标准：连续运行 24 小时，单模块重启/拔插不影响其他 Runtime，所有通知均携带正确模块别名。

## 里程碑 3：网络接口精确绑定

- 通过 IOKit 父子关系建立 USB location → `IOEthernetInterface` → `enX` 映射。
- 流量统计、4G 出口检测和默认路由展示限定到当前 Device ID。
- 模式切换进入 `re-enumerating` 状态，保留原 Device ID 和操作进度。
- 检测多模块 DHCP 网段、网关、MAC 是否冲突。

完成标准：切换页面中的模块时，网络接口和流量始终对应所选物理模块。

## 里程碑 4：发布前完善

- 增加设备级 Bark/别名配置迁移回滚测试。
- 增加 USB 枚举、重复 IMEI、掉线重连和网络 owner 的故障注入测试。
- 更新安装说明和多模块排障页面。
- 在 Apple Silicon/macOS 13 及当前 macOS 各完成一轮发行包验证。

## 暂不纳入

- 多模块同时作为默认出口。
- 带宽聚合、自动负载均衡和故障转移。
- 修改模块固件、内部 DHCP 网段或 MAC 地址。

这些能力需要先确认多台模块在 macOS 下是否暴露重复私网和网关，再决定采用策略路由、按接口绑定代理，或维持单活动上网模块策略。
