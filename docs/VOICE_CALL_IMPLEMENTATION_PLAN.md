# DJOneHub 语音通话实施计划

## 目标

在保留现有多模块架构的前提下，为 macOS 增加按模块选择的拨号、接听、挂断、
DTMF、双向音频、静音和录音能力。第一版全局只允许一个活动音频会话；其他模块
仍可继续收发短信、轮询状态和显示来电。

参考实现来自 `DJOneHub-mac-enhanced` 的 MaVo 音频路径，但不直接复制其单模块
设备发现逻辑。所有会改变模块状态或占用音频设备的操作都必须绑定到明确的
Device ID 和物理 USB 端口。

## 架构边界

- Go 后端负责每台模块的 AT 通话控制、CLCC 状态、初始化状态、模块侧 D4/UAC
  路由和设备级 API。
- macOS Swift 音频宿主负责 UAC PCM、AVAudioEngine、麦克风权限、静音和录音。
- 语音媒体只能在 CLCC 报告 `active` 后启动；通话结束或模块掉线时先停止主机
  音频，再停止模块侧路由。
- 模块侧运行时不进入仓库和安装包；只能在用户明确确认后从固定上游版本下载，
  校验 SHA-256 后写入本地缓存。
- Windows 只提供通话状态和控制，不宣称支持双向音频。

## 阶段与验收

### 阶段 1：设备级通话控制

- 增加拨号、接听、拒接、挂断和 DTMF API。
- 所有写操作使用当前模块的 `operationMu`，避免与短信、eSIM 和后台轮询串扰。
- 网页端所有请求继续通过 `/api/devices/{deviceID}/...` 路由。
- 增加号码校验、状态校验、重复操作抑制和单元测试。

完成标准：两个模拟 Runtime 的请求不会串台；现有 Go 测试全部通过。

### 阶段 2：模块初始化与精确 ADB 绑定

- 为 `usbDeviceLocator` 增加 IOKit registry location ID，同时保留 bus + port chain。
- 将 ADB 打开接口改为接收明确 locator，禁止“打开第一个匹配设备”。
- 按 Device ID 保存 USB 配置备份、初始化状态和运行时状态。
- 检测旧 UAC 配置的 QADBKEY challenge，只有用户输入官方 passcode 后才解锁 ADB；
  passcode 不写入状态文件、备份或日志。
- 用户确认后启用 UAC/ADB 与 IMS/VoLTE；完整语音目标必须精确回读 ADB 与 UAC 均为 1。
- 模块重枚举后使用物理端口恢复原 Runtime；验证失败自动回滚。

完成标准：连接两台相同模块时，ADB 命令、初始化和运行时下发始终命中所选模块。

代码状态：已完成；硬件验收待执行。

### 阶段 3：模块侧语音路由

- 接入固定版本、固定哈希的外部 MaVo 模块运行时。
- 在拨号/接听前加载并检查驱动、保留 ADB session；活动通话建立后复用该 session
  启动 D4/UAC route，避免 active 状态下重新握手超时。
- 通话结束、模块掉线、进程退出时实现幂等停止和残留进程清理。
- 状态 API 返回准备中、已就绪、失败原因和上游运行时校验状态。

完成标准：目标模块的 UAC 接口只在活动通话期间承载语音，另一台模块不受影响。

代码状态：已完成；硬件验收待执行。

### 阶段 4：macOS 双向音频

- 迁移 MaVo 的 Swift UAC probe、8 kHz PCM 和 AVAudioEngine 音频宿主。
- 原生 App 按选中 Device ID 请求配置，并以 VID/PID/IOKit location ID 精确绑定。
- 增加全局音频会话仲裁：同一时间只允许一台模块占用麦克风和扬声器。
- 增加麦克风权限、静音、录音、音频健康状态和异常清理。

完成标准：30 秒呼入和呼出测试均实现清晰双向语音，拔出活动模块后音频资源可恢复。

代码状态：已完成并通过 Apple Silicon Release 构建；硬件验收待执行。

### 阶段 5：多模块与发布验收

- 使用至少两台模块验证同时来电、切换页面、拒接、接听和活动会话冲突提示。
- 验证 USB Hub 断电、单模块重启、枚举顺序变化和 App 重启。

完成标准：无跨模块控制、无音频串台、无残留路由；未完成真机验收前保留“实验性”标识。

## 主要风险与控制

- **错误模块绑定**：ADB、AT、UAC 三条链路必须共享同一 Device ID/物理 locator。
- **同时通话**：后端增加全局音频 owner，第二路接听前必须释放第一路。
- **USB 重枚举**：初始化状态不依赖临时 USB address，统一使用稳定 port chain 恢复。
- **模块兼容性**：先校验内核版本、root 权限、声卡节点和 IMS/VoLTE，再允许拨号音频。
- **音质与实时性**：不在 Go 中再实现第二套音频泵；以 Swift MaVo 路径作为唯一生产媒体路径。
- **分发合规**：内核模块和模块 helper 不随 DJOneHub 分发，保留来源、版本、哈希和用户确认记录。
