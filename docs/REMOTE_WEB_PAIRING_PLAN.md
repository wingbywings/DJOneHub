# 全流程 Web 配对与已注册设备管理方案

日期：2026-10-12。状态：**待用户确认，尚未实施**。
基于 `codex/remote-iphone-callkit` 当前工作区；与 R04–R11 的媒体恢复任务分别推进。

## 1. 目标与范围

将现有独立 Mac 配对窗口及首次 Hub 登记操作迁入已有 Web 管理端，新增 Relay 管理 Web 服务。
从模块选择、申请授权、批准/下载授权、Mac 注册、手机二维码、已配对设备管理，到目标手机选择，日常操作均由 UI 完成。
不再让用户手填模块 ID、手机安装 ID，也不要求执行 provision/enroll/pair/revoke CLI。

“所有 UI 迁移”的实施范围为**注册、配对、授权和设备管理界面**。iPhone 保留扫码/服务器与模块确认、系统权限和 CallKit 通话界面，这是自研 iOS App 接入系统电话的必要部分；Web 展示 Hub 的通话记录，既有 iPhone 本机记录不自动上传。
Relay、证书/DNS 和 Mac 服务首次安装仍属于部署步骤；完成部署后业务管理由 Web 操作。macOS Keychain 和 iOS 权限提示仍由系统展示。

## 2. 当前实现与需要替换的部分

| 当前 | 方案 |
| --- | --- |
| Relay CLI provision | Relay Web 登录、申请审核、签发与下载授权文件 |
| Mac CLI enroll | Mac Web 注册向导、授权文件导入、Keychain 持久化 |
| 独立 DJOneHubRemote / remote-ui | 迁入 Mac Web 的“远程接听与配对”页，退出主要发行入口 |
| 原生窗口生成 QR / 安装列表 / revoke | Mac Web 同一页面完成 |
| Web 手填目标安装 ID | 授权有效且覆盖当前模块的手机下拉选择 |
| 现有单个 profile 的 CLI status | Web profile 列表、状态、当前连接及恢复提示 |
| 手工重启以使用 profile | Web 连接/断开、保存启动选择，重启后按已选 profile 恢复 |
| Relay 仅列有效安装、无管理登录 | 新增管理身份、申请/Hub/手机/授权生命周期和审计 |

保留 CLI 作为兼容及故障恢复工具。迁移后不要求用户打开独立 Mac 配对窗口。

## 3. 架构与部署

```text
本机浏览器 → Mac 现有 Web 127.0.0.1:7575
                 ├─ 现有 USB 模块清单 / 别名 / 状态
                 ├─ 新增配对管理服务 → 当前用户 Keychain
                 └─ 原生 HTTPS 客户端 → 公网 Relay /v1 接口

管理员浏览器 → Relay 管理 HTTPS 站点 → 新管理服务（回环 18444）
                                           └─ 现有身份数据库的受控管理操作

iPhone → HTTPS/WSS/PushKit/CallKit → 现有 Relay 与媒体链路
```

- Mac：在已有 Web 增加页面和经过鉴权的管理 API；不把 Keychain 或 native bootstrap token 交给网页。
- Relay：新增独立可部署的 Go Web 管理服务，默认回环 `127.0.0.1:18444`，由 Nginx HTTPS 反代；现有 Relay `127.0.0.1:18443` 不改端口。
- 推荐独立管理域名，例如 `https://relay-admin.oops.work`（**规划地址，需 DNS 和证书，尚未创建**）。与现有网站 JS 和管理 Cookie 分离；主信令 origin 仍为 `https://oops.work`。
- 管理服务与 Relay 共用既有 identity 存储层/事务/撤销通知能力。采用独立进程时补充跨进程撤销检测：Relay 每秒核对身份撤销版本，目标为 2 秒内使相关 WSS 观察到撤销；蜂窝通话仍执行既有有界收尾。不能只调用管理进程内通知后假定活动 WSS 已关闭。
- 管理账户/session/审计存于单独私有管理数据库；身份和 grant 的 schema 升级由版本化迁移协调。管理进程不运行 shell provision，也不读取 APNs `.p8` 或 TURN 主密钥作为网页数据。
- 浏览器不跨域调用 Mac 的 localhost。首次申请由 Mac Go 后端提交，避免 HTTPS 页面访问本机 HTTP 和 CORS 的问题。

## 4. 模块选择：所有页面共用正确 ID

### 4.1 Mac 页面

候选直接取现有 `/api/devices`，复用已有别名/在线状态：

`Xiaomi · 在线 · IMEI 末尾 / USB 位置`，展开详情显示只读真实 ID。

选择值始终为后台 ID；别名只用于展示。多个模块同名时以设备特征区分。

- 首次申请：只允许勾选已发现且当前可用的模块；无设备则提示连接/刷新。
- 手机配对：可选集合为 **Mac 已知设备 ∩ 该 Hub 已授权模块**；已知离线模块可展示，但需标识离线，不能用它证明语音已就绪。
- 未授权模块显示原因与“申请授权”入口，不能手填 ID 绕过。
- 已授权但本机不再发现的模块保留在只读历史/授权范围中，不进入新的默认候选。
- 别名变化、USB 重枚举或模块离线都不改写选中的 ID；提交前服务端重新校验。

### 4.2 Relay 页面

Relay 无法自动发现 USB。候选来源为 Mac 的**签名注册申请快照**以及已注册 Hub 的授权清单。
管理员在候选列表内勾选，不能随意输入新的模块 ID。

申请显示的硬件和别名是该 Mac 提交的声明；签名证明申请由对应私钥持有者提交，不构成硬件真实性证明。首次申请需要管理员核对 Mac 页面中的申请编号/公钥指纹后批准，不能让未注册请求自行获得权限。

### 4.3 目标手机选择

当前模块可选手机 = 当前 profile 的未撤销安装身份，且其授权范围包含当前模块。
按“手机备注名 · 安装 ID短摘要 · 推送状态”展示；真实 ID可复制但不作为表单输入。

保存时再次查询/验证关系和模块状态；非法、已撤销或属于其他 Hub 的目标拒绝保存。旧配置中失效的 ID显示“授权失效/待重新选择”，不自动切到另一部手机。

## 5. Mac Web 页面

新增主导航“远程接听与配对”，不依赖当前模块选中状态来隐式决定全局 profile。

### A. Relay / Mac 注册向导

1. 填写 Relay HTTPS origin、Mac 显示名称；profile 名自动生成，可在高级项查看。
2. 从当前 Web 设备列表勾选模块。
3. 本机生成身份密钥，先在 Keychain 持久化待注册状态，再生成并签名申请。
4. 点击“提交注册申请”；后台提交到 Relay，页面显示申请编号、公钥指纹和待审核状态。
5. 点击“打开 Relay 授权管理”，在另一个页面用管理员身份审核。
6. 管理员下载批准后的授权文件，返回 Mac Web 导入；显示服务器、模块、到期时间和对应申请，再确认注册。
7. Go 后端校验申请/公钥/origin 绑定并消费授权，保存身份到 Keychain。页面显示 ready。
8. 点击“连接此 Relay”，无需停整个 Hub；可勾选重启后自动连接。

申请也可下载为**不含私钥/访问 token**的 JSON，在 Relay 管理页导入，用于不方便直接提交的环境。授权导入完成后提示删除浏览器下载目录中的交付文件。

首版把“管理员审核后下载 → Mac 导入”作为明确可审阅的闭环，不采用网页 SSH 自动登录服务器。以后可增加 Mac 持有密钥签名领取批准结果的一键路径，此项不作为本次完成的前提。

### B. 已注册 Mac / profiles

表格显示备注名、Relay、profile、Hub ID摘要、授权模块、注册状态、信令连接状态、最近错误。
支持查看详情、连接/断开、设为重启后默认、移除本机配置。

- 首版允许登记多个 profile，**同时仅一个活动 Relay 连接**，沿用现有 Hub 调度模型。
- 新增私有 profile 索引；兼容原 Keychain profile，提供 UI“导入已有配置”输入旧名称一次（如 home-xiaomi），读取后列表化。不得把 Keychain seed/token 写进索引。
- 活动通话/振铃/收尾或 journal 未确认时禁止切换 profile 和破坏性本机移除；UI 提示具体原因。
- 本机移除不等于服务器撤销，分别展示并说明影响。复用已有不确定凭据事务恢复逻辑，失败状态不会自动重试旧 grant/refresh token。

### C. 手机配对与管理

选择已注册 profile → 勾选已授权模块 → 可填手机备注 → 生成一次性 QR（5 分钟）或下载 JSON → iPhone 扫码确认。

页面显示到期时间和“取消/撤销此配对邀请”；服务端新增未消费 grant 撤销能力。隐藏二维码仅隐藏，取消明确使授权失效。

配对期间轮询或事件刷新安装列表，确认新身份属于此次邀请；用 grant 与安装的持久关系关联，不能根据“列表多了一条”猜测。
备注以 Hub 授权关系绑定到真实 installation，支持修改。

配对完成显示“应用到已选择模块”，列出逐模块变更预览及 AI 当前状态；用户确认后逐项保存，报告成功/失败。**不承诺跨模块原子事务**：遇到活动通话时部分模块可拒绝，失败项可重试，不能静默回滚已生效的配置。

表格列出有效/撤销安装、授权模块、配对时间、备注、推送注册环境/状态与是否被模块引用；在线状态区分当前 WSS 在线、仅后台推送可用、离线/未知，未知不伪造在线。
支持查看、备注、复制 ID、撤销。撤销前列出受影响模块/通话；撤销后将引用标记失效，不自动改为其他手机。

### D. 模块路由

保留现有“来电 → iPhone 远程接听”，替换文本 ID为关联手机选择器。可从全局管理页跳转到对应模块。
AI 配置优先不变；页面明确显示实际生效路由，不因为选择手机就偷偷关闭 AI。需要切到手机时单独确认关闭 AI；两步操作的失败各自展示。

## 6. Relay Web 管理页面

### 管理员登录 / 初始化

首次部署生成短时一次性 setup 凭据，存于 root/服务用户可读私有文件；部署者通过现有服务器访问取得，用管理网页设置管理员账号和密码。初始化后失效，不存在公开无鉴权 provision 接口。
管理员密码采用现代密码哈希，Cookie Session、退出/过期、登录限流与 CSRF。首版面向单管理员单 tenant 部署，但后台操作仍按 tenant 过滤，避免以后扩展时越权。

### 注册申请

列表：申请编号、Mac 名称、公钥指纹、申请模块、创建/到期时间、pending/approved/rejected/expired/completed。
详情显示只读模块 ID和声明的别名；可批准原范围或子集、拒绝、撤销未完成授权。tenant 由管理员已获权限决定，申请不能自己选择管理权限。

### 授权文件

已批准申请点击“签发并下载授权文件”，有效期 10 分钟，绑定目标 Mac 公钥、申请和 Relay origin。
新增带版本号的交付 envelope；Mac Web 识别新 envelope，旧 CLI grant 文件保留兼容导入路径并明确标识旧格式。

服务端仅保存 secret 哈希，不能日后显示原 secret。因此：首次下载即时签发；再次下载使用“重新签发并下载”，原未消费授权在同一事务中失效。已消费项只能查看结果，不能重新消费或重新下载长期凭据。
网络响应丢失时允许重新签发未消费授权；若已完成登记则进入结果查询/恢复。审批/下载/消费和重签发并发时使用事务保证最多一次登记。

下载采用已登录同源请求、私有响应/no-store、attachment，secret 不在 URL/日志/审计中，不生成永久公网下载链接。
授权生命周期包括未签发、已签发、已消费、已过期、已撤销，并显示关联 Hub。浏览器下载后的文件不等同服务器登录凭据。

### 已注册 / 已配对管理

- Hub 列表：名称、tenant、公钥指纹、授权模块、注册/撤销状态、最近实际认证活动；查看子手机及关联申请。
- 手机列表：所属 Hub、备注、模块范围、配对时间、撤销状态、推送注册状态；不显示 APNs device token。
- 管理员可撤销手机或 Hub。Hub 撤销明确提示子安装受影响和当前通话可能中断。
- 注册/配对审计：谁批准/拒绝/下载/重新签发/撤销、对象、时间、结果；不记录密钥/secret/电话号码。
- 单独展示 identity、信令、TURN、APNs 配置加载状态及构建版本；健康不等于已完成真实通话验收。

首版不支持就地任意改写已经消费的身份模块范围。新增/调整范围通过新的注册/配对授权流程完成，并提供替代旧身份的指引，避免 token 范围、子安装和活动通话不一致。

## 7. 身份、会话与数据设计

### Mac Web 管理鉴权

现有 Web 只有基础响应头，不能把原生凭据接口直接公开给所有 localhost 请求。新增管理会话：

- 启动器通过本机受控机制打开管理页，交换短时一次性票据；票据不写日志/命令行、不与 native-control token 共用，进入 URL时仅用 fragment 并立即清除。
- 第一次已授权会话可设置本机管理密码；之后直接访问网页可用该密码登录，日常不要求命令行输入凭据。
- Session HttpOnly、SameSite Strict，短时管理会话；敏感 API检查 loopback、合法 Host、精确 Origin、CSRF 和 JSON 类型。禁止跨域 CORS，浏览器不持有 Relay access/refresh token。
- localhost 使用可兼容 HTTP 的本机会话策略，Relay HTTPS Session 另设 Secure，避免给 HTTP Cookie 错设 Secure 导致无法登录。
- 普通页面可保留现有状态显示；涉及注册、配对 secret、切换 profile、撤销等必须授权。新增远程路由保存也经过管理鉴权；既有其他 API的全面鉴权改造另列范围，避免误称已有页面全部得到保护。

### Relay 管理面

独立 HTTPS 管理站点，管理 Session 与 `/v1` 身份 Bearer 不互换。现有 `/v1` 原生 Origin 限制保持，管理服务只接受自己的同源浏览器请求。
未注册申请提交只接收有大小/数量/速率限制、到期约束和持钥证明的申请，写入 pending；不能签发授权。拒绝额外 URL、任意文件路径或自声明管理员字段。

### 新增数据

- `enrollment_requests`：申请、公钥/持钥证明、候选模块快照、状态、管理员、到期、关联授权和最终 Hub。
- grant 绑定/撤销/结果关系：关联 request/public key，手机 grant → installation；保留已有 hash-only secret 约束。
- identity 管理元数据：名称、创建时间、撤销时间、最近认证时间；在线状态用实际连接观测，不用“注册过”等价在线。
- `admin_accounts/sessions/audit`：独立私有管理数据库。
- 本机 `profiles` 非敏感索引、活动连接选择、启动设置：原子写；密钥和不确定事务仍在 Keychain。

数据库迁移须支持已有身份、未填新元数据的旧记录（显示未知/旧记录，不造时间），备份和版本检查明确。独立管理进程的轮换/撤销操作与 Relay 同时访问时需跨进程一致性验证。

## 8. API 草案（实施时锁定字段与错误码）

| 位置 | API / 操作 | 权限 |
| --- | --- | --- |
| Mac | `/api/remote-management/session/*`：登录/退出 | 本机受控初始化 / 管理密码 |
| Mac | `/api/remote-management/profiles`：列表/导入旧配置/详情/本机移除 | 管理会话 |
| Mac | `/api/remote-management/enrollment-requests`：候选/创建/提交/状态 | 管理会话，服务端校验设备 |
| Mac | `/api/remote-management/enroll`：导入并消费授权 | 管理会话，绑定待登记密钥 |
| Mac | `/api/remote-management/connection`：连接/断开/重启后默认 | 管理会话，通话状态门控 |
| Mac | `/api/remote-management/pairings`：QR/文件/状态/撤销邀请 | 管理会话，限定 Hub 授权模块 |
| Mac | `/api/remote-management/installations`：列表/详情/备注/撤销 | 管理会话，Hub 所属关系 |
| Mac | 原 `/api/devices/{id}/remote-calls/config`：选择手机保存 | 管理会话，重校验 installation |
| Relay native | `/v1/enrollment-requests`：签名提交首次申请/受限查询 | 持钥证明与限流，无审批权 |
| Relay native | `/v1/pairings`：补充邀请状态/撤销/结果关联 | 当前已鉴权 Hub |
| Relay admin | `/admin/api/session/*` | 管理员身份 |
| Relay admin | `/admin/api/requests/*`、`grants/*`：审核、签发下载、撤销 | 管理员及 tenant 范围 |
| Relay admin | `/admin/api/hubs/*`、`installations/*`、`audit` | 管理员及 tenant 范围 |

GET 状态无副作用；签发、重签发、连接、撤销用明确写请求。异步 Keychain/网络操作提供 job ID与明确进行中/结果，超时不等于远端未消费。错误按身份不确定、模块已离线、权限不足、活动通话、签名/到期和网络分类展示。

## 9. 实施阶段与交付

| 阶段 | 工作 | 交付 / 验收 | 预计人日 |
| --- | --- | --- | --- |

| W02 | Relay 管理服务、登录、申请审核、文件下载、安装部署 | Web 审核→文件下载闭环、HTTPS部署说明 | 3–4 |

## 10. 完成标准

- 新 Mac 可在 Web 勾选已有模块、提交申请；Relay Web 审批和下载；Mac Web 导入完成 Keychain 登记，不执行 provision/enroll 命令。
- Mac 和 Relay均可在管理页查到正确 Hub、授权范围、公钥指纹与状态。
- Mac Web 生成手机 QR，iPhone 确认配对后 Web明确显示该次邀请的结果，目标手机下拉可选择，不手填模块/安装 ID。
- 错别名、重复别名、模块断开/切换、跨 Hub/tenant、过期/被撤销身份都不能误授予/误绑定。
- 取消邀请后即使拿到旧 QR也无法配对；重复消费、重复下载及并发批准最多产生合法的一次登记。
- Relay 管理进程撤销身份后，Relay 信令在约定的有界检测周期内断开，不能只在管理进程内生效。
- 已有 home-xiaomi 和手机覆盖升级后可继续使用；新老数据库迁移、备份和凭据不确定状态恢复通过。
- Web连接/切换 profile 不产生双 Hub WSS，不影响活动通话；重启自动选择已保存 profile。
- 普通网页/其他网站不能调用 Keychain管理、下载 grant或撤销身份；secret不落 URL query、localStorage、日志和长期下载链接。
- 使用新流程完成前台及锁屏后台双向通话、手机/主叫两端挂断、第二通接听，并验证 AI开时不触发远程。
