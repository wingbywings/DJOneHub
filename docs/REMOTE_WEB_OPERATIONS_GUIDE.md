# Web 注册、配对与日常运行指南

更新：2026-10-13，最新包为 `DJOneHub-macOS-arm64-web-management-20261013.zip`，在 Web 配对版本上补齐健康、在线观测和管理跳转。代码与自动化验证已落地；公网管理服务、现有 Mac 服务尚未替换，临时身份浏览器配对管理验收已通过，真实设备升级验收仍待完成。旧 R11 发行包没有本文的新页面，升级前继续使用[旧版本指南](REMOTE_OPERATIONS_GUIDE.md)。

## 1. 两个管理入口

| 入口 | 用途 |
| --- | --- |
| Mac 本机 `http://127.0.0.1:7575/remote/` | Mac 申请/登记、配置列表、连接/断开、手机 QR/文件、邀请与手机管理、模块目标选择 |
| Relay 管理 HTTPS 站点，例如 `https://relay-admin.oops.work/admin/` | 管理员登录、批准 Mac 申请模块、授权文件下载、远端 Mac/iPhone 身份撤销与审计 |
| 原生 Relay `https://oops.work` | Mac 和 iPhone 的原生鉴权/信令/推送接口；不是管理网页 |

管理域名是部署示例，目前没有替你建立公网服务。部署方法见[Relay 管理服务指南](REMOTE_RELAY_WEB_ADMIN_DEPLOY.md)。模块管理仍在 Mac 根页面，导航新增“远程接听与配对”，新页可返回模块管理。

Mac 管理必须在该 Mac 的浏览器使用明确的本机地址；局域网 IP 或任意 Host 不能登录敏感管理接口。HTTP 本机会话和 HTTPS Relay 管理会话相互独立，手机不需要登录管理员账户。

## 2. 安装、重启与打开页面

结束活动通话后，安装完整的新 Mac ZIP：解压，在发行目录执行 `./install`。安装器可能要求管理员权限，日常运行使用当前登录用户，不加 sudo。升级不会重新登记或清理已有 Keychain/iPhone 身份。

```sh
djonehub stop
djonehub start
```

新启动器普通 `start` 就会同时启用 Hub、原生音频控制和 AudioHost，打开 Web 远程管理页面。启动终端保持打开，Ctrl+C 或另一个终端的 `djonehub stop` 停止服务。没有单独的 restart 命令。

```sh
djonehub open    # 重新打开并交换一次性本机管理票据
djonehub status
djonehub logs
```

启动器通过私有原生通道获得两分钟、一次性票据，用系统 API 打开页面；不把票据放进日志或进程参数。页面立即清除 URL fragment，再建立约 30 分钟的管理会话。直接访问 URL 则使用已设置的本机管理密码；首次由启动器授权后，可在页面底部设置密码。过期会话重新打开或登录即可，不需要重新配对。

旧命令 `djonehub start --remote-profile home-xiaomi` 仍可使用：读取该旧 profile，加入列表并保存为下次启动选择。新包中的 `remote-ui` 是打开 Web 页的兼容入口，独立 Mac 配对窗口不再随主要发行包提供。CLI `remote help/status/pair/revoke` 保留用于旧版本兼容或故障处理。

`--demo` 仍是无硬件演示，不启动真实 Web 配对服务。手动运行二进制时，需启用 `--native-control-file` 并使用 remoteopus 构建；正常使用直接运行新发行启动器即可。

## 3. 已有配对：迁移一次，后续不再手填 profile

1. 打开“注册此 Mac”中的“导入已经保存在钥匙串中的旧配置”。
2. 输入原来使用的 profile 名称，例如本线程的 `home-xiaomi`，可填写显示备注。这里输入的是旧本机配置名称，不是模块 ID，也不上传 token。
3. 点击“读取并加入列表”。核对服务器、公钥指纹、登记状态和授权范围。Keychain 访问提示由 macOS 展示，允许刚更新的 DJOneHub 访问原记录；网页刷新不重复读取钥匙串。
4. 在“当前连接”选择已登记配置，勾选“下次启动自动连接此配置”，点击连接并确认。
5. 上方信令状态达到 `online` 后，可在手机列表读取原有 iPhone；不必重新扫码。配置卡片显示 Hub ID，支持复制 Hub ID、公钥指纹及申请编号；可保存或修改 Relay 管理地址。

以后只用 `djonehub start` 即按已保存的配置连接。连接时取消自动连接勾选会清除旧的重启选择。“断开（保留重启选择）”只停当前连接；“断开并取消自动连接”同时清除重启选择。活动通话、来电和未完成恢复会拒绝切换。切换配置不会把模块旧目标自动改成其他手机。

## 4. 新 Mac：全部通过 Web 登记

### Mac 创建申请

1. 连接实际 USB 模块，等待其在原模块管理页显示可用。
2. 打开远程管理，填写 Mac 备注和原生 Relay 地址，例如 `https://oops.work`。可另外填写已部署的 Relay 管理 HTTPS origin，例如 `https://relay-admin.oops.work`；提交申请后可从卡片直接打开管理页。这里不会自动创建域名或猜测管理地址。
3. 勾选实际发现的模块。页面同时显示别名和只读真实 ID；同名模块不会合并，不能手填 ID扩大范围。
4. 点击“创建签名注册申请”。Mac 先把新密钥保存到当前用户 Keychain，再展示公有申请；密钥不会上传到管理网页。
5. 在该申请中点击“提交到 Relay”。如果 Relay 尚未启用申请提交接口，可点击“下载公有申请文件”，交给管理员从 Relay 管理页导入。

申请有效期约 30 分钟。模块离线时直接提交会拒绝，重新连接后再试。已过期申请需新建，不覆盖原 profile 或复用旧密钥事务。

### Relay 管理员审批

1. 登录管理 HTTPS 页，找到申请或导入公有申请文件。
2. 对照 Mac 页面核对申请编号和公钥 SHA-256 指纹，再选择申请中的模块或子集并批准。
3. 点击“签发 / 重新签发并下载”，在页面内确认后下载授权 JSON。

授权最长十分钟，且不会晚于申请到期；绑定这次申请和 Mac 公钥。重新签发使旧的未消费文件失效。候选别名/硬件是 Mac 的声明，签名只证明持钥关系，管理员仍需核对来源。tenant 由管理员服务配置确定，申请不能自行选择权限。

### Mac 导入并登记

1. 回到对应申请，选择下载的授权 JSON。
2. 在页面内核对申请、服务器、模块和有效期，确认写入 Keychain 并消费授权。
3. 显示“已登记”后，选择该配置连接，按需保存下次启动选择。
4. 删除已交付的授权副本。

新 Web 向导只接收版本 2 的绑定授权文件；旧 CLI enrollment grant 不能直接塞入此向导。旧身份用上一节导入已有 profile，不重新消费旧文件。

钥匙串和网络操作显示后台任务。刷新页面可检查“正在进行的操作”，超时不代表服务器未消费。若显示 `enrolling` 或 `refresh_pending`，先重新读取状态；仍不确定时，从新申请重新登记并由 Relay 管理员处理旧身份，不反复消费旧授权。

## 5. iPhone 配对、邀请与设备管理

1. 在“配对 iPhone”选择已登记的 Mac 配置，填写手机备注。
2. 勾选“本机已知设备 ∩ 该 Hub 已授权模块”。离线设备会标明离线；授权不代表其音频已就绪。
3. 生成五分钟、一次性二维码。用现有 iPhone App 的“扫描 Hub 配对二维码”扫码，在手机核对服务器/模块/期限后确认。
4. 页面查询这个 grant 的消费结果，显示准确的 `ios_...` 安装身份，不选择“列表里最新的一部手机”。
5. 若不能扫码，下载配对 JSON，经私有传输送到手机，选择 App 的“导入 Hub 配对文件”。配对后删除交付副本。

等待扫码期间页面周期查询结果。过期/撤销/已消费时隐藏二维码并清除临时交付内容。二维码无法生成时可减少一次所选模块，或改用文件；文件同样只授权本次选择。

“读取邀请列表”查看所选配置最近 128 个邀请，包括未使用、过期、撤销和对应的已消费身份。页面刷新/进程重启不会把旧 secret 再展示，仍可撤销未使用邀请。撤销已消费邀请不能代替撤销手机身份。

“读取手机列表”查看所选配置的有效/撤销手机、授权模块、备注、配对/认证时间、WSS 连接观测和推送登记，可复制手机 ID／公钥指纹。旧记录缺少时间时显示未知；推送登记不代表当前在线。读取后每五秒更新连接观测，后台查询不会重新读取 Keychain；临时网络失败显示未知并继续重试，查询凭据到期需手动重新读取列表。旧 Relay 未提供在线字段时保持未知，需同时升级 Relay。WSS 未连接的手机仍可能通过 APNs 后台来电；物理断网需等心跳检测，不承诺瞬时下线。支持备注和撤销；撤销前展示引用该手机的本机模块和通话情况，可能中断正在使用它的远程通话。旧模块引用会保持原 ID，显示失效，不自动指向另一部手机。

## 6. 给模块选择目标手机

配对不会自动启用远程路由。有两种 UI 方式：

- 远程管理中的“各模块的接听目标”：读取模块配置，在下拉中选择有效且覆盖该模块的 iPhone，保存该模块。
- 原模块管理 → 选择实际模块 → “来电” → 展开“iPhone 远程接听”：目标栏已改成手机下拉，不再粘贴安装 ID。需先登录本机管理、连接 profile 并重新读取。全局模块卡片的“打开此模块的来电设置”会携带真实模块 ID；指定模块不可用时提示选择，不静默跳到另一模块。

手机属于当前活动 Hub、未撤销、覆盖该模块时才出现。保存时后端再次请求授权列表并校验；页面的旧列表不能绕过服务器检查。旧目标失效时明确显示失效，不自动选另一部手机。离线模块、活动通话或未完成恢复拒绝保存。

扫码完成后，“应用到此次配对的模块”会先显示逐模块预览及 AI 状态，再逐项保存。成功项立即生效，失败项单独报告，不承诺跨模块原子事务，也不自动回滚已保存项。

**AI 启用时仍只走 AI，不发远程来电；AI 出错不会自动转手机。** 保存远程目标不会偷偷关闭 AI。如果希望使用 iPhone 接听，到对应模块 AI 设置中明确关闭 AI并保存。响铃超时和来电显示仍可在原模块设置中调整。

旧 `configure-remote-answering.sh` 在检测到新 Web 鉴权边界时，会在修改 AI 前停止，提示使用 Web；`--check-only` 仍可只读核对。

## 7. 撤销与本机删除的区别

- Mac Web“撤销手机”：使这个安装失去服务器权限，相关远程通话可能收尾；手机本机清理凭据不会替代服务器撤销。
- Relay Web“撤销 Mac”：使该 Hub 及子手机身份失效；旧 native/WSS 进程会检测跨进程撤销。
- Mac Web“删除本机配置”：先断开，再删除本机 Keychain 与列表条目、清除相关重启选择；**不撤销服务器身份或尚在有效期内的邀请**。如要取消所有远程权限，先在 Relay 管理页撤销 Hub。

换机或确需重新配对时，先撤销旧安装，再在 iPhone 恢复页确认并清理本机凭据，最后创建新邀请。普通软件升级不需要清理。

## 8. Relay 部署与日常重启

首次新增管理服务需要单独部署；必须先升级 native Relay 到支持 schema 3 的版本，再启动会共享身份库的管理服务。旧 schema 2 二进制不能读取迁移后的数据库。用一致快照备份，回退数据库时不能把新消费的身份混回旧快照。

详细步骤、systemd/Nginx 模板、域名/证书和初始化账户见 [Relay Web 部署指南](REMOTE_RELAY_WEB_ADMIN_DEPLOY.md)。当前原生 Relay 可增加 `--public-origin https://oops.work` 接收 Mac 直接提交，升级脚本会保留该参数。APNs `.p8`、sandbox/production 和 TURN 配置沿用已有部署，不把它们上传到配对页面。

结束通话后在服务器执行：

```sh
sudo systemctl restart djonehub-relay
sudo systemctl restart djonehub-relay-admin
```

如果只重启管理服务，无需重启 native Relay；它只使管理会话失效。coturn、Nginx 和证书仅在其配置改变或实际故障时按现有部署方式处理。

## 9. 验证与版本边界

本次 Go/SQLite/HTTPS/WSS/QR 和 JavaScript 回归使用临时身份通过，不代表已经替换你的公网或 Mac 服务。已在解锁后的浏览器用临时身份完成注册申请、审批、授权导入、连接切换、二维码及列表筛选验收，详见[验收记录](remote-web-browser-acceptance.md)。真实安装、旧 profile 导入、iPhone 扫码和前台/锁屏双向来电仍需实际升级后核对。

现有 iPhone App 已兼容版本 1 的 QR/配对文件，本次 Web 迁移不要求清理或重新安装已有手机。R06 并行媒体迁移、R07 AudioHost 故障恢复、弱网/长通话和 iOS 发布签名等原计划差距未由本次 UI 迁移关闭。恢复/续租/DTMF 开关仍沿用旧指南，默认不自动开启。

## 9. Relay 健康与身份跳转

Relay 管理页“服务与权限”每五秒读取正在运行的 Relay 私有快照，显示采样时间、Relay 构建和启动时间、信令进程、当前管理范围的 WSS 连接数、身份数据库查询、TURN 签发配置／最近结果、APNs 环境／最近结果及成功失败计数。

Relay 每秒在身份目录生成 `runtime-status.json`（0600），两个服务必须使用同一系统用户和同一 `--state-dir`。快照超过八秒即显示过期、在线状态未知；缺失、不安全权限、不同用户或旧 Relay 没有快照时也显示未知。状态文件不包含电话内容、APNs 地址、访问凭据或私钥，不需要开放新的公网状态端口。

TURN 签发成功只证明凭据生成成功，APNs 接受请求只证明提供方接受；媒体连通和手机实际收到仍需端到端观测，页面不会把未测项标为正常。计数从 Relay 进程启动开始，重启归零。

身份列表分别显示授权、WSS 和推送状态，支持复制身份 ID、公钥指纹；点击“所属 Hub”跳转到对应 Mac 行。首次使用新增展示前，先升级 Relay 原生服务及管理服务，再升级 Mac 包。新增展示的浏览器点击验收记录见[展示补齐记录](remote-web-display-batch.md)。
