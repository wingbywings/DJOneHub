# Web 注册与配对管理浏览器验收

2026-10-13，分支 `codex/remote-iphone-callkit`。用户解锁 Mac 后，用浏览器实际点击本机临时测试服务。所有 Hub、手机、授权和数据库均为临时测试身份；未读取真实 Keychain、APNs 私钥或修改现有服务。

## 已通过的页面流程

- Mac 登录 → 从两个同名模块中只选 module_b → 创建签名申请 → 提交原生临时 TLS Relay。
- 独立 Relay 管理页登录，核对同一申请编号/指纹和 module_b 范围 → 批准 → 页面确认签发下载。页面显示下载已触发、待导入及成功审计。
- 临时测试服务以 0600 文件保存该次成功下载响应，浏览器文件选择器将同一授权上传 Mac 页面，预览服务器/申请/范围/期限后确认，登记完成。
- Mac 连接下拉选择新配置，确认切换后显示 online，并保存重启选择；Relay 页面刷新显示授权已消费、对应 Hub 已注册及正确公钥/模块。
- 新配置的手机配对候选只包含 module_b。生成 QR PNG、手机备注、五分钟期限显示正常；手机列表为空，旧 Hub 的 module_a 手机不会进入候选。模块接听目标也只显示 module_b，候选手机为空。
- 在另一临时页面核对已配对 module_a 手机下拉、目标保存、精确邀请结果及历史邀请列表。撤销未消费邀请后，二维码清除、配对文件和再次撤销按钮禁用，历史列表显示已撤销。

浏览器自动化的下载等待接口曾长时间不返回；改为直接点击并核对页面与临时服务的实际响应完成验收。未获取浏览器下载目录文件，不能把此次记录理解为下载目录落盘验收。真实 iPhone 扫码和通话不在临时浏览器流程内。
